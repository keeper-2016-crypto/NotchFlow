# Подписанные обновления NotchFlow

## Состояние реализации

Клиент, загрузка, интерфейс и локальная подпись реализованы. Реальное обновление установленной 0.3.5 в чистой Windows ещё не проверено: Windows Sandbox не найден. Не считать интеграцию установки окончательно готовой до этого прогона.

Текущая версия исходников и основного установщика — 0.3.6; AssemblyVersion/FileVersion — 0.3.6.0, InformationalVersion — 0.3.6. Пакет подготовлен локально, не опубликован. Отдельные LOCAL-TEST сборки 0.3.6/0.3.7 предназначены только для VM. Инструкция проверки: RELEASE-0.3.6-TESTING.md.

## Протокол и защита

- Манифест: https://195.78.49.209:8443/notchflow/version.json
- Отдельная подпись: тот же адрес с суффиксом `.sig`. Файл содержит Base64 RSA-PSS/SHA-256 подписи **точных байтов** JSON (UTF-8 без BOM). Нельзя менять пробелы, переводы строк или форматировать JSON после подписания.
- Только после проверки подписи JSON разбирается. Канал `stable`, платформа `win-x64`; числовая версия из трёх или четырёх компонентов. Установка равной/старой версии запрещена.
- Разрешены только HTTPS, тот же узел и порт, путь `/notchflow/releases/<имя>.exe`; query, fragment, credentials и redirects запрещены. Обычная системная TLS-проверка остаётся включённой, pinning сертификата Let's Encrypt не используется.
- Максимум манифеста 64 КиБ, установщика 512 МиБ. Скачивание потоковое в уникальный `.part`, общий срок до 15 минут. Проверяются Content-Length при наличии, фактический размер и SHA-256. Отмена/ошибка удаляет текущий `.part`.
- Кэш повторно проверяется. Перед запуском повторно проверяются подпись и файл; файл удерживается открытым без разрешения записи/удаления до запуска процесса.
- Приватный ключ не попадает в приложение. Подпись манифеста не заменяет Authenticode: Windows может показывать предупреждение об отсутствии подписи издателя самого EXE.

## Ключ разработчика

Открытый ключ включён ресурсом `NotchFlow/Assets/UpdatePublicKey.pem`.

Приватный ключ хранится только локально, вне репозитория:
`%LOCALAPPDATA%\NotchFlowReleaseKeys\update-signing-key.dpapi`.

RSA 3072. Каталог ограничен текущим пользователем Windows. Ключ зашифрован DPAPI CurrentUser. Не отправлять его, резервную копию или пароль на VPS, GitHub, в логи или артефакты. Процесс, уже работающий с правами этого пользователя, может расшифровать DPAPI: защищайте учётную запись разработчика.

**Сделать резервную копию самостоятельно:**

```powershell
pwsh -File scripts/Backup-UpdateSigningKey.ps1 -Destination E:\PrivateBackup\notchflow-signing-key.encrypted.pem
```

Выбрать собственный защищённый внешний каталог. Скрипт интерактивно спрашивает длинный пароль и создаёт AES-256 зашифрованный PKCS#8. Пароль хранить отдельно. Простое копирование `.dpapi` не гарантирует восстановление на другой Windows/учётной записи. Для восстановления импортировать зашифрованный PKCS#8 с паролем в RSA, сверить открытый ключ с встроенным и заново защитить приватные байты DPAPI на новой машине. Резервное копирование и восстановление в этой сессии не выполнялись.

`New-UpdateSigningKey.ps1` нужен для первоначальной генерации. Не запускать заново и не заменять открытый ключ уже выпущенных клиентов без отдельного плана ротации.

## Подготовка выпуска

PowerShell 7 на машине разработчика:

```powershell
pwsh -File scripts/Prepare-UpdateRelease.ps1 `
  -Installer C:\Releases\NotchFlow-0.3.6-Setup.exe `
  -Version 0.3.6 `
  -ReleaseNotesFile C:\Releases\notes.txt `
  -OutputDirectory C:\Releases\signed-0.3.6
```

Это пример будущего выпуска, не существующий production-артефакт. Убедиться, что версия установщика и приложения совпадает с параметром. Скрипт создаёт `version.json`, `version.json.sig` и `releases/<installer>.exe`, проверяет подпись встроенным открытым ключом и повторяет проверку хеша. Ничего не загружает на сервер.

## Миграция VPS (только после разрешения владельца)

1. Прогнать установленную старую версию в одноразовой Windows VM; проверить заметки/задачи/настройки, каталог, ярлыки, отмену, ошибки, успешное обновление и повторный запуск.
2. Собрать bootstrap-установщик с этой системой и встроенным открытым ключом. Старая 0.3.5 не умеет проверять новую подпись; первый переход для таких клиентов выполняется вручную.
3. Подписать проверенный новый установщик локальным инструментом. Сохранить предыдущий серверный комплект для отката публикации.
4. Сначала загрузить новый установщик под новым неизменяемым именем. Не заменять существующий 0.3.5.
5. Загрузить манифест и подпись во временные имена и согласованно заменить рабочую пару. Для существующей статической схемы краткое несовпадение пары безопасно: клиент откажет в проверке. Для атомарного переключения каталога потребуется отдельный согласованный план; Nginx в этой работе не менялся.
6. Проверить скачанные с HTTPS исходные байты и подпись, затем проверку клиентом. Не загружать `.build/signed-package-test`: это неисполняемый тестовый образец, не релиз.

## Поведение приложения

Проверка через 8 секунд после запуска, затем через 12 часов. Последняя попытка и успешная проверка сохраняются отдельно в `Updates/state.json`; автоматическая проверка ограничена 12 часами и между перезапусками. Ручная проверка может выполняться раньше. Автоматические проверки отключаются в настройках. Ни одна настройка не включает автоматическую установку.

Пользователь выбирает «Обновить сейчас», затем после проверки — «Установить». «Позже» не запускает EXE. Загрузка может быть отменена. При установке сохраняется черновик открытых настроек и пользовательские данные, запускается отдельный интерактивный Inno Setup, приложение штатно завершается. Используются прежний AppId, каталог и пользовательский режим; `/UPDATEAPP=1` включает запуск приложения после успешной установки. Ошибки собственно установки показывает интерактивный установщик. Автоматический откат бинарников отдельным сервисом не реализован; полагаться на неподтверждённое восстановление после сбоя нельзя.

Для переносной/тестовой копии без `unins000.exe` установка из интерфейса запрещена, чтобы не устанавливать приложение в каталог разработки.

## Проверки

Локальный TCP/HTTP-стенд и временные ключи: новые/равные/старые версии, подпись до JSON, неизвестный ключ, повреждённые байты/JSON/Base64, отсутствие подписи, ограничения платформы/канала/URL/размера, HTTP-ошибки, отказ соединения, SHA-256, Content-Length, обрыв, отмена, отсутствие параллельных загрузок, очистка `.part`, повторная проверка кэша и файла перед запуском, 12-часовой интервал и сохранение состояния. `UpdateUiTests` проверяет, что «Позже» не вызывает установку.

Настоящий production-манифест проверен только чтением: клиент отклонил отсутствие подписи и ничего не скачивал/запускал. Локальный инструмент создал тестовый подписанный комплект; клиент проверил его встроенным открытым ключом. Проверка не выдаётся за тест реального установщика.

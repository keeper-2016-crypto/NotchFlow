# NotchFlow 0.3.6 — проверка обновления в отдельной Windows

Статус: пакеты собраны; 196 автоматических проверок пройдены; проверка реальной загрузки по локальному HTTP пройдена. Полная установка/обновление Windows ещё НЕ проверены. Ничего не опубликовано.

## Что находится в комплекте

- `0.3.6/NotchFlow.exe`, `0.3.7/NotchFlow.exe`: self-contained тестовые приложения.
- `NotchFlow-0.3.6-LOCAL-TEST-Setup.exe`: начальная установка в виртуальной машине.
- `NotchFlow-0.3.7-LOCAL-TEST-Setup.exe`: настоящий установщик предлагаемого обновления.
- `server/notchflow/version.json`, `version.json.sig`, `releases/NotchFlow-0.3.7-Setup.exe`: подписанный пакет локального сервера.
- `Start-LocalUpdateServer.ps1`: сервер только на 127.0.0.1:8765.

LOCAL-TEST сборки используют только локальный адрес, но настоящий встроенный открытый ключ. Никогда не публиковать их на VPS/GitHub. Их AppId совпадает с основным приложением: устанавливать только в отдельную тестовую Windows, иначе они заменят рабочую установку!

Основной установщик для последующего выпуска: `D:\Projects\NotchFlow\Installer\NotchFlow-0.3.6-Setup.exe`. Основной EXE: `D:\Projects\NotchFlow\dist\release-0_3_6\Portable\NotchFlow.exe`. Основная сборка обращается к production HTTPS, локальный сервер для неё не подходит.

## Реальный тест 0.3.6 → 0.3.7

1. Подготовить отдельную Windows 11 x64 22H2 или новее (VM с контрольной точкой). Скопировать в неё всю папку `update-e2e`. Закрытый ключ туда НЕ копировать. .NET отдельно не устанавливать.
2. Отключить внешний интернет, оставив loopback. Установить `NotchFlow-0.3.6-LOCAL-TEST-Setup.exe`. Проверить, что установка и запуск работают без скачивания Runtime.
3. Убедиться в версии 0.3.6 в настройках. Изменить акцент, положение острова, настройки автозапуска. Создать заметку и задачу с уникальным текстом, отметить ещё одну задачу выполненной. Штатно закрыть приложение, сохранить копию `%LOCALAPPDATA%\NotchFlow` вне каталога установки и запустить вновь.
4. В PowerShell, открытом в папке комплекта, выполнить:
   `powershell -NoProfile -File .\Start-LocalUpdateServer.ps1`
   Окно оставить открытым. Сервер не требует администратора. При занятом порте остановить предыдущий тестовый сервер; клиент настроен на порт 8765.
5. В настройках приложения вручную проверить обновления. Должно появиться окно с текущей 0.3.6 и новой 0.3.7. Сначала нажать «Позже»: установка не должна запускаться.
6. Повторить проверку и выбрать загрузку. Дождаться окончания и появления отдельного предложения установки. До подтверждения EXE не должен запускаться. Файл будет проверен по подписи манифеста, размеру и SHA-256.
7. Подтвердить установку. Убедиться, что старая NotchFlow закрылась, появился интерактивный Inno Setup, каталог остался прежним. Завершить установку. Должна запуститься новая NotchFlow 0.3.7.
8. Проверить все созданные заметки/задачи, их состояние и выбранные настройки. Сравнивать содержимое данных, а не побайтово весь каталог: состояние обновления и логи закономерно изменяются.
9. В «Установленных приложениях» должна остаться одна NotchFlow. В диспетчере задач — один процесс NotchFlow.exe. Повторный запуск ярлыка не должен создавать второй экземпляр. Перезапуск Windows должен сохранять данные и прежнее поведение автозапуска.
10. Закрыть локальный сервер через Ctrl+C. Сохранить результат и скриншоты с номерами версий. Для повторения восстановить контрольную точку VM.

Дополнительно: отменить загрузку; проверить повторную попытку. На копии локального пакета испортить один символ version.json без повторной подписи: клиент должен отклонить обновление. Затем восстановить оригинал. Эти проверки не затрагивают VPS.

## Совместимость с 0.3.5

На отдельной контрольной точке установить сохранённый `Installer/NotchFlow-0.3.5-Setup.exe`, создать тестовые данные и затем вручную установить ОСНОВНОЙ 0.3.6 поверх него. Проверить прежний каталог, единственную запись установки, все данные и запуск. Это отдельная проверка миграции 0.3.5; одной проверки 0.3.6 → 0.3.7 недостаточно.

## Ключ и резервная копия

Используется существующий RSA-3072, RSA-PSS/SHA-256. Открытый ключ встроен как `NotchFlow.UpdatePublicKey.pem`. SHA-256 SPKI: `533D5BE602764FF9D94132106494543EC95380E1A54E674E8FDB53F39624F1BC`.

Закрытый ключ на компьютере разработчика: `C:\Users\Admin\AppData\Local\NotchFlowReleaseKeys\update-signing-key.dpapi`. Защита DPAPI CurrentUser и ACL только текущего пользователя. В Git и готовые пакеты он не включён. Новый ключ не создавался.

На исходном компьютере в PowerShell 7 выполнить `scripts/Backup-UpdateSigningKey.ps1 -Destination <путь-вне-репозитория-на-защищённом-носителе>/notchflow-signing-backup.pem`. Скрипт интерактивно запросит длинную уникальную парольную фразу (не менее 16 символов), создаст зашифрованный PKCS#8 AES-256-CBC/PBKDF2-SHA256 с 600000 итерациями. Хранить резервную копию офлайн на зашифрованном носителе, пароль отдельно в менеджере паролей. Не помещать файл в Git, установщик, публичную папку или VPS. Простое копирование DPAPI-файла не является переносимой резервной копией. Саму резервную копию в этой работе не создавали: пароль выбирает владелец.

## Будущая публикация — сейчас не выполнять

`scripts/Prepare-UpdateRelease.ps1` создаёт manifest, detached signature и копию установщика, проверяя подпись существующим открытым ключом. Подготовленный основной пакет: `dist/signed-0.3.6`. Инструкция и пример команды: `docs/SIGNED-UPDATES.md`.

Сначала пройти обе ручные проверки, сделать защищённую резервную копию ключа и обеспечить HTTPS-доставку version.json + version.json.sig + установщика. Ключ на VPS не нужен. Манифест и подпись должны публиковаться согласованно; установщик — раньше манифеста. Текущий production version.json не изменялся. Готовность к публикации пока условная: реальный Windows E2E не пройден.
